壹

它做什么

给一个家庭用的系统，不是对外开放的社交网络。源码在 wangBoYi972/family-platform。本页只转述仓库里已经写明的结构。

后端按服务拆开，各自持有自己的数据，由网关做统一入口。管理端顶栏写着「把时间，留给家人」。家庭端和移动端的面板尽量只留一份，放在 apps/shared。

下面可以跳到架构图里对应的服务。家居和账本已经有 Dockerfile，也进了编排和 Prometheus 抓取。

贰

核心场景

右侧是可点击的示例界面，数据是中性的演示数据，不会请求后端。左侧说明对应哪个服务、代码里实际做到哪一步。

智能家居控制

family-iot-svc。每家一条中枢：真实的 Home Assistant，或内置演示中枢 demo://local。家庭端面板是设备卡片，点进去才是明细控制。

  • 本机和私网默认可绑定。公网主机必须写在 FAMILY_IOT_ALLOWED_HOSTS 里，按主机名精确匹配。云元数据地址始终拒绝。
  • 访问令牌加密后保存。接口不回传令牌，也不回传中枢地址。发现接口只回「已连接 / 未绑定 / 暂时不可达」这类文案。
  • 命令包括灯、开关、场景，以及空调温度（16–35）、模式、风速，电视音响的音量、静音、频道和播放。越界参数返回 400。
  • 真实中枢在服务启动和绑定后会连 WebSocket，状态变化写回快照；演示中枢跳过。这条连接仍要求地址通过私网校验。手动设备按家庭隔离，同步不会覆盖；当前解绑会清掉该家庭全部设备快照。

家庭账本与分摊

family-ledger-svc。金额是整数分。分类只有餐饮、日用、住房、交通、医疗、教育、其他，未知分类直接 400。

  • 支出必须写垫付人和分摊，分摊合计等于这笔账。收入记在收款人名下，不分摊。
  • 本月收支和每人净额由服务端按整月计算，不按当前页加总。净额 = 收入 + 垫付 − 分摊。
  • 改删只限记账人或管理员。家庭编号只取已校验会话。
  • 家庭端和移动端已接共享面板。管理端还没有入口。

私密与健康档案

family-archive-svc。档案正文、用药计划和复诊内容都加密存放。可见范围是「仅自己」或「家庭成员」。

  • 设为仅自己可见时，其他成员和管理员都看不到。
  • 家庭端和移动端当天提醒一次未服用的药，以及当天的复诊。同一天不重复。
  • 微信订阅消息模板尚未接入，这条链路不会发出订阅消息，也不会弹微信授权。
  • 管理员可以看近 30 天的访问汇总，按人、按天、按动作聚合。

家庭协同内容

family-content-svc。任务、公告、日历、纪念日、动态和相册都按家庭存放。列表可以按关键字或状态检索，并支持分页。

  • 任务能指派、开始、完成。逾期口径和列表筛选共用同一段条件。
  • 相册时光轴可以导出一份单文件 HTML 纪念册，图片内嵌，不依赖登录态。
  • 别的设备改了数据，会经 Outbox 推成 refresh，只重拉相关面板。

即时消息与音视频

family-im-svc 负责会话和消息，family-media-svc 负责通话信令。媒体走 WebRTC，服务器不转发音视频。

  • 文本、图片、语音和文件。新消息在事务提交后整帧推送，断线退回轮询。
  • 私聊只投递给双方。已读回执也走推送。两分钟内可撤回自己的消息。
  • 默认仍是 mesh，最多 8 人。LiveKit SFU 已能签发入房凭证，默认关闭；打开且凭据齐全时上限 20 人，关掉就回到 mesh。
  • 凭证只发给这通通话的参与者，房间名由服务端按通话生成。通话纪要仍在设备上混音分段。公网压测还没有写成已完成。

可选家庭小助手

family-ai-svc。它查询的是这个用户原本就能看到的任务、日程、纪念日和内容，权限沿用现有校验。

  • 未配置模型时默认关闭。/api/ai/chat 返回 503，前端写成「AI 助手未配置」。
  • 配置之后以 SSE 流式回答，并提示正在调用哪个工具。
  • 历史按用户和家庭保留最近 40 条，不写入即时消息库。换设备可以接着看。
  • 通话转写也走这个服务。模型不可用时纪要停在失败，可以重试。

English

A system for one household

family-platform is a household-scoped system, not a public social network. The backend is Java 21 with Spring Boot 3.3.5, Spring Cloud 2023.0.3 and Spring Cloud Alibaba 2023.0.3.2. family-gateway is the only public API entrance: it routes HTTP and WebSocket calls and checks JWTs. Household id comes from the checked session, never from a client-supplied family id.

Ten runnable services: gateway, members, content, files, archives, messaging, calls, an optional family assistant, home devices, and a ledger. Four libraries sit beside them: family-common, family-security, family-messaging and family-api. They are not separate processes.

Four clients share the APIs. The admin web (port 5173) accepts only an ADMIN session whose client is admin, and shows tasks, members, archives, notices, calendar and assistant settings. The mobile app (5175) and the family mini program (5174) both sign in as client=family and share panels for tasks, ledger, calendar, albums, chat, calls, home devices and health. The archive mini program (5176) signs in as client=archive. Its screen is login plus the archive list. The server additionally allows that client to call auth routes and to GET archives, files, notices and /api/users/me. Other calls are forbidden.

Home devices bind to Home Assistant on loopback or a private address by default. A public hostname is accepted only when it is listed exactly in FAMILY_IOT_ALLOWED_HOSTS. Cloud metadata hosts are always rejected. Tokens are encrypted and are not returned, nor is the hub address. The discovery response is a status sentence only. Commands cover lights, switches, scenes, climate temperature (16–35), mode and fan speed, and media-player volume, mute, source and playback. Out-of-range parameters return 400. A real hub gets a WebSocket on startup and after binding, and state changes are written back to the snapshot. The demo hub skips that socket and only updates the local snapshot. Manual devices are household-scoped, editable only when marked MANUAL, and are not overwritten by a sync. Unbind currently deletes every device snapshot in that household. The live socket still requires an address that passes the private-network check. Both home and ledger now have Dockerfiles, compose services and Prometheus scrape jobs on ports 8092 and 8093. The admin console still has no screen for either.

The assistant stays off until a model is configured. Unconfigured chat returns 503. Calls default to WebRTC mesh, one-to-one and up to eight people. LiveKit SFU join tokens are implemented and stay off unless enabled: the cap is then 20, the token is issued only to a participant of that household’s live call, and turning the flag off returns the service to mesh. This repository does not record a production load test. Recordings are still mixed on the device. WeChat subscribe-message templates for medication and follow-up reminders are not connected.

The repo now includes nine Prometheus alert rules, an Alertmanager config, and backup plus isolated-database restore drill scripts. Those files are not a completed production drill. Still open before launch: MySQL and Nacos integration, real SMS or WeChat identity, object storage, public TURN tests, a production SFU load test, mini program device regression, and running the alert and backup drills against the real environment.
