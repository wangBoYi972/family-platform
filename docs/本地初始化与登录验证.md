# 本地初始化与登录验证

## 前置条件

1. 运行 `infra/docker-compose.yml` 中的 Nacos、MySQL 和 Redis。
2. 创建数据库用户 `family_app`，并通过环境变量设置 `FAMILY_DB_PASSWORD`。
3. 使用至少 32 字节的随机值设置 `FAMILY_JWT_SECRET`。
4. 仅在开发环境设置 `FAMILY_AUTH_MOCK_CODE`，并显式开启 `family.auth.mock-login-enabled`。

## 初始化首位管理员

Flyway 创建表后，在受控环境中执行以下 SQL，并将手机号替换为实际家庭管理员号码：

```sql
INSERT INTO family_household (name) VALUES ('我的家庭');
INSERT INTO family_white_list (phone, household_id, role, enabled)
VALUES ('实际管理员手机号', 1, 'ADMIN', TRUE);
```

不要在 Git、配置文件、日志或接口响应中保存数据库密码和 JWT 密钥。

## 开放注册与邀请码

注册接口 `POST /api/auth/register` 对所有人开放（网关与服务端都放行了匿名访问），
但**必须填写管理员发放的邀请码**，校验不通过一律返回 403 且不会创建任何账号或凭据。

| 环节 | 说明 |
| --- | --- |
| 发放 | 管理员在「账号与家庭成员 → 注册邀请码」生成，可指定角色（成员/管理员）、可注册人数（1–10）、有效期（1–720 小时） |
| 形态 | 明文形如 `FAM-7K2M-QX4P`，去掉了 0/O/1/I；**只在生成接口返回一次**，库里只存 SHA-256 摘要与尾号 |
| 校验 | 不存在 / 已作废 / 已过期 / 已用尽 → 拒绝；管理端注册只接受管理员邀请码，成员邀请码需在小程序端使用 |
| 归属 | 加入哪个家庭、拿到什么角色由邀请码决定，注册人无法自选；仍受「每户最多十位启用成员」限制 |
| 限流 | 同一手机号 10 分钟内最多 5 次注册尝试，超出返回 429 |

管理员接口（需 ADMIN 令牌）：`GET /api/users/invite-codes`、`POST /api/users/invite-codes`、
`DELETE /api/users/invite-codes/{id}`（作废）。列表只回显尾号，不返回明文。
