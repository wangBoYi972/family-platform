# 家庭账本设计

## 1. 目标与范围

家庭账本让家庭成员能记录一笔支出或收入，并在打开页面时直接看到本月收支和每个人的净额。

完成标准是：成员能填金额、分类、日期、垫付人、分摊人；页面能看到本月收入、支出，以及每个人“该收 / 该付 / 持平”的金额。净额必须由服务端按整月账目计算，前端不能用当前加载的一页自行加总。

本轮实现覆盖：

- 新后端服务 `family-ledger-svc`，端口 `8093`，包名 `com.familyhome.ledger`。
- 服务分层参照 `family-content-svc`：`controller / service / mapper / model / dto / vo`。
- 网关路由、本地无 Nacos 配置、MySQL + Flyway 建表。
- 唯一一份共享面板 `apps/shared/panels/LedgerPanel.vue`，家庭端与移动端共用。
- 后端集成测试与前端分摊逻辑单测。

## 2. 模块与配置

### 2.1 后端模块

`backend/family-ledger-svc` 已挂入 `backend/pom.xml` 的 `<modules>`。

分层职责：

| 层 | 目录 | 说明 |
| --- | --- | --- |
| 控制器 | `controller/LedgerController.java` | 只做参数绑定、会话 principal 透传和统一 `ApiResponse` 包装 |
| 服务 | `service/LedgerService.java`、`service/impl/LedgerServiceImpl.java` | 分类、分摊、权限、汇总的全部业务规则 |
| Mapper | `mapper/LedgerEntryMapper.java`、`mapper/LedgerSplitMapper.java` | MyBatis-Plus 查询与写入 |
| 模型 | `model/LedgerEntry.java`、`model/LedgerSplit.java` | 表映射 |
| 入参 | `dto/LedgerEntrySaveDTO.java`、`dto/LedgerSplitDTO.java` | 刻意不含 `householdId`、`createdBy` |
| 出参 | `vo/LedgerEntryVO.java`、`vo/LedgerSplitVO.java`、`vo/LedgerSummaryVO.java`、`vo/LedgerMemberNetVO.java` | 金额字段统一以分返回 |

家庭编号和记账人只从已校验会话取。`LedgerEntrySaveDTO` 没有家庭编号或记账人字段，客户端即使传额外字段也不会参与落库。成员资格通过 `MemberCacheService` 向 user-svc 取本家庭启用成员白名单；其他家庭或已停用成员不会进入白名单。

### 2.2 本地配置

`application-local.yml`：

- 服务地址：`127.0.0.1:8093`
- Nacos discovery：关闭
- 数据库：`jdbc:mysql://localhost:3306/family_ledger`，账号 `root` / `root`
- Flyway：开启，历史表 `flyway_schema_history_ledger`
- user-svc：`http://127.0.0.1:8081`

`application.yml` 中 Nacos  prod 路由使用 `lb://family-ledger-svc`；`application-local.yml` 中本机路由使用 `http://127.0.0.1:8093`，路径均为 `/api/ledger/**`。

## 3. 数据模型

Flyway 迁移：`backend/family-ledger-svc/src/main/resources/db/migration/V1__ledger.sql`。

### 3.1 `ledger_entry`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT PK AUTO_INCREMENT | 账目 ID |
| `household_id` | BIGINT NOT NULL | 家庭编号，来自会话 |
| `type` | VARCHAR(16) | `EXPENSE` 或 `INCOME`，CHECK 约束 |
| `amount_cents` | BIGINT | 金额，整数分，`> 0`，禁止浮点 |
| `category` | VARCHAR(32) | 固定分类之一 |
| `note` | VARCHAR(200) NULL | 备注 |
| `occurred_on` | DATE | 发生日期 |
| `created_by` | BIGINT | 记账人，来自会话 |
| `payer_id` | BIGINT | 支出时为垫付人，收入时为收款人 |
| `created_at` | TIMESTAMP | 创建时间 |

索引：`(household_id, occurred_on DESC)`、`(household_id, payer_id)`。

### 3.2 `ledger_split`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT PK AUTO_INCREMENT | 分摊行 ID |
| `entry_id` | BIGINT | 账目 ID，外键级联删除 |
| `household_id` | BIGINT | 冗余家庭号，查询时双保险 |
| `member_id` | BIGINT | 分摊成员 |
| `amount_cents` | BIGINT | 该成员承担的整数分，`> 0` |

唯一键 `(entry_id, member_id)` 防止同一成员重复分摊；索引 `(household_id, entry_id)` 支持按家庭聚合。

## 4. 接口契约

所有接口都挂在 `/api/ledger` 下，网关前缀为 `/api/ledger/**`。

### 4.1 写入与改删

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| POST | `/api/ledger/entries` | 任一启用成员 |
| PUT | `/api/ledger/entries/{id}` | 记账人本人或管理员 |
| DELETE | `/api/ledger/entries/{id}` | 记账人本人或管理员 |

请求体字段：

```json
{
  "type": "EXPENSE",
  "amountCents": 1234,
  "category": "餐饮",
  "note": "周末聚餐",
  "occurredOn": "2026-11-22",
  "payerId": 11,
  "splits": [
    { "memberId": 11, "amountCents": 617 },
    { "memberId": 12, "amountCents": 617 }
  ]
}
```

校验规则：

- `type` 只能是 `EXPENSE` 或 `INCOME`。
- `amountCents` 必须是正整数分，不能是浮点或 0。
- 分类固定为：`餐饮、日用、住房、交通、医疗、教育、其他`；未知分类返回 400，不静默归到“其他”。
- `note` 最长 200 字；日期格式 `yyyy-MM-dd`。
- 垫付人 / 收款人必须在当前家庭启用成员白名单内。
- 收入不分摊：`splits` 必须为空，金额记在收款人名下。
- 支出至少一名分摊人；同一成员不能重复；每人分额必须为正整数分；总和必须等于账单金额，否则返回 400。
- 分摊总额用 `Math.addExact` 累加，溢出也返回 400，避免 long 回绕产生负金额。
- 更新 / 删除时，跨家庭账目统一返回 404；同家庭非本人且非管理员返回 403。

### 4.2 分页列表

`GET /api/ledger/entries?page=1&size=10&month=2026-11&category=餐饮&payerId=11&keyword=聚餐`

- `month` 格式 `yyyy-MM`，按发生日期做左闭右开区间。
- `category` 传 `ALL` 或不传表示不过滤；其他值必须在固定分类内。
- `payerId` 按垫付人 / 收款人筛选。
- `keyword` 匹配备注或分类。
- 所有查询都带 `household_id = 会话家庭号`。权限条件和关键字的 `OR` 分别用 `and(...)` 分组，避免 `(note LIKE ? OR category LIKE ?)` 越过家庭隔离。
- 分摊行按本页账目 ID 一次性 `IN` 查询后分组，避免 N+1。

### 4.3 月度汇总

`GET /api/ledger/summary?month=2026-11`

返回：

```json
{
  "month": "2026-11",
  "incomeCents": 500,
  "expenseCents": 1000,
  "members": [
    {
      "memberId": 11,
      "displayName": "爸爸",
      "incomeCents": 0,
      "paidCents": 1000,
      "shareCents": 400,
      "netCents": 600
    }
  ]
}
```

计算口径：

- 汇总读整月账目，不受列表分页影响。
- 当前启用成员即使本月没有账也会返回，净额为 0。
- 支出净额：`垫付金额 - 自己承担的分摊`；收入净额：`收到的收入`。
- `netCents = incomeCents + paidCents - shareCents`。
- 支出在成员之间内部抵消，因此所有成员净额之和等于本月收入总额。
- 历史脏数据若缺少分摊行，服务端把整笔支出挂到垫付人身上，保证净额总和不失衡。

## 5. 前端实现

共享面板只有一份：`apps/shared/panels/LedgerPanel.vue`。

- 表单：类型（支出 / 收入）、金额（元输入，内部转分）、固定分类、发生日期、垫付人 / 收款人、备注。
- 分摊：默认按启用成员平均分摊，余数从前往后每人多 1 分；可切换为指定金额。
- 提交前通过 `apps/shared/ledger-split.mjs` 校验，复用服务端的同一套规则口径。
- 列表分页使用现有 `usePagedList` 与 `ListMore`，筛选条件变化时刷新列表和汇总。
- 汇总独立请求 `/ledger/summary?month=...`，不拿当前页本地加总。
- 删除前用 `uni.showModal` 二次确认。
- 编辑 / 删除按钮只对记账人本人或管理员显示；服务端仍会再校验一次。

接入位置：

- 家庭端 `apps/mini-family/src/pages/index/index.vue`：主 tab 增加“账本”。
- 移动端 `apps/mobile-app/src/pages/index/index.vue`：主 tab 增加“账本”，沿用现有横向滚动，不塞进“我的家”。

两个 Vite 配置都固定了 `host: "127.0.0.1"`，保证 `http://127.0.0.1:5174/` 与 `http://127.0.0.1:5175/` 可直接访问。

## 6. 测试

### 6.1 后端

`backend/family-ledger-svc/src/test/java/com/familyhome/ledger/LedgerIntegrationTest.java`，使用 H2 MySQL 兼容模式与 mock 成员白名单。

已覆盖 7 组用例：

1. 分摊总和不等于账单时返回 400，且不写入任何账目。
2. 未知分类返回 400；金额只接受整数分。
3. 跨家庭成员、已停用成员不能被分摊。
4. 成员只能改删自己的账，管理员可改删；跨家庭账目视为不存在。
5. 月度汇总按整月算净额，且与分页列表收支口径一致；上月账目不混入。
6. 金额全程用整数分：0.1 元 + 0.2 元 = 30 分，无浮点尾巴。
7. 月份 / 分类 / 垫付人 / 关键字筛选下推数据库，关键字不会越过家庭隔离。

运行命令：

```bash
mvn -f backend/pom.xml -pl family-ledger-svc -am -Dtest=LedgerIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false test
```

分摊逻辑抽成纯模块 `apps/shared/ledger-split.mjs`，单测 `apps/shared/ledger-split.test.mjs`。

运行命令：

```bash
node --test apps/shared/ledger-split.test.mjs
```

## 7. 浏览器验收

使用本地网关 `127.0.0.1:8080` 与两个前端地址实测：

1. 家庭端 `http://127.0.0.1:5174/`：登录后主 tab 出现“账本”；记一笔 `0.10` 元支出，月汇总显示支出 `¥0.10`，垫付人与另一成员净额分别为 `该收 ¥0.05`、`该付 ¥0.05`。

5. 返回任务 tab 与聊天 tab，页面正常加载，未被账本改动破坏。

## 8. 联调中修复的既有问题

这些不是账本业务引入的改动，但不修复会挡住验收：

- `family-content-svc` 的启动类同时声明了 `@EnableFeignClients(basePackages = "com.familyhome.api")`，而 `ServiceSecurity → ServiceClients` 又用 `@EnableFeignClients(clients = ...)` 注册同一批客户端，导致 `FeignClientSpecification` 重名。已移除启动类上重复的注解，保留 `ServiceClients` 统一装配。
- 移动端 `apps/mobile-app/src/App.vue` 包装 `uni.getStorageSync` 等方法时调用了包装后的自身，形成无限递归，登录态读不出来。已按家庭端写法先保存 `nativeUni` 再包装。
- 两个前端 Vite 配置原先只监听 IPv6 localhost，已固定监听 `127.0.0.1`。

## 9. 注意事项

- 不要提交 git；本轮所有改动只保留在工作区。
- 金额展示用整数分除以 100 的字符串处理，不用 `toFixed`，避免 `0.30000000000000004`。
- 不要把 `householdId` 加到请求 DTO 里；家庭边界必须由服务端会话决定。
- 新增分类需要同时改服务端 `CATEGORIES` 与前端 `LEDGER_CATEGORIES`，否则一端放行一端拦截。
