# 架构改进记录

## 改进日期
2025-01-XX

## 问题诊断

从架构角度发现以下问题:

1. **服务间调用缺少容错**: Feign Client 调用无降级策略,依赖服务故障会导致级联失败
2. **频繁的远程调用**: 每次任务操作都调用 user-svc 获取成员信息,无缓存
3. **Token 手动透传**: Authorization 头需要在每个方法手动传递,容易遗漏
4. **缺少统一异常处理**: 各服务异常处理不统一,返回格式不一致
5. **Feign 降级未启用**: 虽有超时配置,但 circuitbreaker 未启用

## 改进措施

### 1. 添加 Feign 降级机制

**新增文件:**
- `backend/family-api/src/main/java/com/familyhome/api/user/feign/UserFeignClientFallback.java`
- `backend/family-api/src/main/java/com/familyhome/api/file/feign/FileFeignClientFallback.java`

**修改文件:**
- `UserFeignClient.java`: 添加 `fallback = UserFeignClientFallback.class`
- `FileFeignClient.java`: 添加 `fallback = FileFeignClientFallback.class`

**效果**: 当 user-svc 或 file-svc 不可用时,返回友好的降级响应,而不是直接抛出异常

### 2. 实现成员信息缓存

**新增文件:**
- `backend/family-api/src/main/java/com/familyhome/api/user/service/MemberCacheService.java`

**修改文件:**
- `backend/family-content-svc/.../TaskServiceImpl.java`: 使用 `MemberCacheService` 替代直接调用 Feign

**缓存策略:**
- TTL: 5 分钟
- 降级策略: 远程调用失败时返回过期缓存
- 按家庭 ID 隔离

**效果**: 减少对 user-svc 的调用频率,提升响应速度,增强容错能力

### 3. 统一 Token 透传

**新增文件:**
- `backend/family-api/src/main/java/com/familyhome/api/config/FeignConfiguration.java`

**实现机制:**
- 使用 Feign RequestInterceptor 自动从 RequestContextHolder 获取当前请求的 Authorization 头
- 自动注入到所有 Feign 请求中

**效果**: 业务代码不再需要手动传递 bearer token

### 4. 统一异常处理

**新增文件:**
- `backend/family-common/src/main/java/com/familyhome/common/exception/GlobalExceptionHandler.java`
- `backend/family-common/src/main/java/com/familyhome/common/exception/ServiceUnavailableException.java`

**处理的异常类型:**
- `ResponseStatusException`: 业务异常
- `MethodArgumentNotValidException`: 参数校验异常
- `IllegalArgumentException`: 非法参数
- `ServiceUnavailableException`: 服务不可用
- `Exception`: 兜底异常处理

**效果**: 所有异常统一转换为 `ApiResponse` 格式,便于前端统一处理

### 5. 启用 Feign 熔断降级

**修改配置文件:**
- `backend/family-content-svc/src/main/resources/application.yml`
- `backend/family-archive-svc/src/main/resources/application.yml`
- `backend/family-file-svc/src/main/resources/application.yml`
- `backend/family-im-svc/src/main/resources/application.yml`

**配置变更:**
```yaml
spring:
  cloud:
    openfeign:
      circuitbreaker:
        enabled: true  # 新增
```

**效果**: 启用 Spring Cloud Circuit Breaker,配合 fallback 实现熔断降级

## 后续建议

### 短期优化
1. ✅ 完成 media-svc 和 user-svc 的相同配置更新
2. 为其他有服务间调用的场景添加缓存(如文件元数据)
3. 添加缓存命中率监控指标
4. 配置熔断器参数(失败率阈值、窗口大小等)

### 中期优化
1. 引入 Redis 作为分布式缓存,替代内存缓存
2. 实现缓存预热和主动刷新机制
3. 添加服务调用链路追踪(已有 traceId,需接入 Zipkin/Jaeger)
4. 实现 Feign 重试策略和幂等性保证

### 长期架构建议
1. **评估服务合并**: 对于家庭场景(< 10 用户),考虑将 user/content/archive 合并为单个核心服务
2. **引入 API 组合层**: 在 Gateway 或新增 BFF 层聚合多个服务调用,减少客户端请求次数
3. **事件驱动改造**: 完善 Outbox 模式,用异步事件替代同步服务调用
4. **读写分离**: 引入 CQRS 模式,查询场景使用物化视图,减少跨服务查询
