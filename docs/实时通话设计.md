# 实时通话设计（WebRTC + WebSocket 信令）

> 范围：家庭成员之间的 1 对 1 音视频通话，以及最多 8 人的家庭多人通话。
> 客户端：家庭端 H5 / 移动端 APP（WebView）。微信小程序不在范围内（不支持 WebRTC）。

## 1. 总体架构

媒体走 WebRTC P2P 直连（网状 mesh），服务端只负责信令、鉴权、状态与通话记录，不中转媒体。

```
家庭端 H5 / APP                                   后端
┌──────────────┐   HTTPS  /api/media/**      ┌──────────────────┐
│ CallPanel    │ ──────────────────────────▶ │ family-gateway   │
│  ├ call-client│   WSS   /ws/call?ticket=…   │  ├ JWT 校验       │
│  └ webrtc-mesh│ ◀─────────────────────────▶ │  └ ws 路由        │
└──────┬───────┘                             └────────┬─────────┘
       │  SDP / ICE（经信令转发）                        │
       │                                    ┌─────────▼─────────┐
       └──────────── RTP/SRTP 直连 ────────▶ │ family-media-svc  │
                （失败时经 coturn 中继）        │  CallSocket       │
                                            │  CallService      │
                                            │  CallSignalBus    │
                                            └───┬────────┬─────┘
                                                │        │
                                          MySQL(family_media)  Redis(跨实例广播)
```

设计取舍：

- **P2P 而不是 SFU**：家庭场景人数少、隐私要求高，P2P 不落媒体、无额外服务、延迟最低。
- **网状而不是星型**：每两人一条 PeerConnection，任何一端掉线不影响其余人。
- **代价**：每个客户端上行 = 人数 − 1 路编码，8 人是音视频的实际上限；超过 8 人需要引入 SFU（LiveKit/mediasoup），本设计不覆盖。

## 2. 服务端组成

| 组件 | 职责 |
| --- | --- |
| `CallController` | REST：发起、接听、拒接、离开、结束、媒体状态、历史、进行中、ICE 配置、WS 票据 |
| `CallService` / `CallServiceImpl` | 状态机与权限：家庭归属校验、人数上限、并发通话互斥、超时回收 |
| `CallSocket` | `/ws/call` 端点：ticket 鉴权、JSON 协议解析、SDP/ICE 转发、心跳、断线宽限 |
| `CallSignalBus` | 信令投递：先投本机连接，再经 Redis `family:call:signal` 广播到其它实例 |
| `IceServerService` | 下发 STUN/TURN，TURN 用 coturn `use-auth-secret` 时效凭据 |
| `CallSessionMapper` / `CallParticipantMapper` | `call_session` / `call_participant` 两张表 |

数据表（`db/migration/V2__call.sql`）：

- `call_session`：`id / household_id / mode(DIRECT|GROUP) / kind(AUDIO|VIDEO) / status / caller_id / end_reason / created_at / answered_at / ended_at`
- `call_participant`：`call_id / user_id / state(INVITED|JOINED|REJECTED|LEFT) / mic_on / cam_on / invited_at / joined_at / left_at`

**SDP 与 ICE 候选绝不落库**，只存在于信令通道与客户端内存，避免隐私泄露与表膨胀。

## 3. 鉴权：一次性票据

WebSocket 无法自定义 Header，把 JWT 拼进 URL 又会进网关/代理日志，因此分两步：

1. `POST /api/media/ws-ticket`（带 JWT）→ 返回 `ticket` + `expiresIn=30`；
2. `wss://host/ws/call?ticket=…` 握手，服务端取出票据内绑定的 `userId/householdId/role`，**用后即焚**。

票据存在 Redis（`family.messaging.enabled=true`）或本机内存（单实例开发），30 秒未使用自动失效。
握手成功后，服务端只信任票据里的身份，客户端上报的任何 `userId` 都不作为权限依据。

网关对 `/ws/call` 使用 `lb:ws://` 显式声明 WebSocket 转发，否则会按 HTTP 处理导致握手 400。

## 4. 信令协议

统一 JSON：`{ "type": "...", "callId": "...", ... }`，缺失或非法字段直接返回 `error` 并保持连接。

### 客户端 → 服务端

| type | 字段 | 说明 |
| --- | --- | --- |
| `call.invite` | `callId`, `to[]` | 由 REST 发起后走信令补推（多端同步） |
| `webrtc.offer` | `callId`, `to`, `sdp` | 转发 offer，仅允许发给同通话内成员 |
| `webrtc.answer` | `callId`, `to`, `sdp` | 转发 answer |
| `webrtc.ice` | `callId`, `to`, `candidate` | 转发 ICE 候选 |
| `call.leave` | `callId` | 离开通话 |
| `ping` | — | 20 秒一次心跳 |

### 服务端 → 客户端

| type | 字段 | 触发 |
| --- | --- | --- |
| `call.invited` | `call` | 有人呼叫你 |
| `call.accepted` | `call`, `user` | 有人接听（含自己的回执，用于统一发起 offer） |
| `call.rejected` | `call`, `user` | 有人拒接 |
| `call.left` | `call`, `user` | 有人离开 |
| `call.ended` | `call`, `reason` | 整通结束（`HANGUP` / `REJECTED` / `NO_ANSWER` / `LEFT`） |
| `call.state` | `user`, `mic`, `cam` | 对方开关麦/摄像头 |
| `webrtc.offer` / `webrtc.answer` / `webrtc.ice` | `sdp` / `candidate`, `from` | 媒体协商转发 |
| `error` | `message` | 非法信令或越权 |
| `pong` | — | 心跳响应 |

越权拦截：`webrtc.*` 转发前校验「发送者与收件人都在该 callId 的参与者表中且未离开」，
否则返回 `error` 而不是静默丢弃，便于排查客户端 bug。

## 5. 状态机

```
call_session:  RINGING ──接听──▶ ACTIVE ──挂断/全员离开──▶ ENDED
                  │
                  ├── 全部拒接（DIRECT 直接结束 / GROUP 保持）
                  └── 45 秒无人接听 ──▶ ENDED(NO_ANSWER)

call_participant:  INVITED ──接听──▶ JOINED ──离开/断线超时──▶ LEFT
                      └──拒接──▶ REJECTED
```

约束：

- 同一用户在同一家庭内只能有 1 通进行中的通话（`activeFor` 校验），避免双呼叫互相打断；
- 1 对 1 呼叫时对方在通话中直接 `409`；多人通话人数上限由 `family.media.max-participants` 控制；
- `end` 只允许发起者或管理员；`leave` 支持参与者自己退出；
- 全员 `LEFT` 后会话自动结束，避免僵尸通话。

## 6. 断线处理

- 客户端 `call-client.js` 自动重连（指数退避，最长 15 秒），重连期间信令进入队列，连上后按序补发；
- 服务端断线后不立即让用户离开通话，而是记一个 **30 秒宽限**（`reconnect-grace-seconds`）；宽限内重连则继续原来的 `callId`；
- 宽限到期仍未重连，由 `CallSocket.flushPendingLeave` 定时任务触发 `leaveIfDisconnected`；
- 心跳 55 秒无消息的服务端会主动关闭连接（网关/负载均衡空闲超时之上留余量）。

效果：地铁过隧道、切 Wi-Fi/4G 不会直接掉线，只有真正离线超过 30 秒才从参与者列表移除。

## 7. TURN 与 NAT 穿透

`IceServerService` 下发两类服务器：

- STUN：`family.media.turn.stun-urls`，默认本机 coturn 的 3478；
- TURN：`family.media.turn.urls`，凭据为 coturn **时效凭据**：
  `username = 过期时间戳:userId`，`credential = Base64(HMAC-SHA1(static-auth-secret, username))`。

凭据默认 1 小时过期，即使被截获也无法长期盗用中继流量；coturn 侧只需 `--use-auth-secret` 与同一个 `static-auth-secret`。

`infra/docker-compose.yml` 内置 `coturn` 服务（host 网络）：监听 `3478/udp+tcp`，中继端口 `49160-49200`。
公网部署必须补 `--external-ip=<公网IP>`，否则返回的 relay 候选不可达，表现为「能接通但没声音/黑屏」。

## 8. 客户端实现

| 文件 | 职责 |
| --- | --- |
| `utils/call-client.js` | 换票、连接、重连、心跳、发送队列 |
| `utils/webrtc-mesh.js` | 本地采集、PeerConnection 池、offer/answer/ICE、禁用轨道、前后摄像头切换 |
| `components/CallVideo.vue` | H5/WebView 下用原生 `<video>` 绑定 `srcObject`（uni 的 `<video>` 不支持 MediaStream） |
| `components/CallPanel.vue` | 呼叫面板、来电弹窗、通话界面、多人宫格、计时、静音/关摄像头/挂断 |

**防 offer 冲突规则**：每对连接只由「后进房间的一方」发 offer（接听方对房间内已有成员发起，发起方只应答）。
`MeshRtc.offerTo` 额外用 `offered` 标记 + `signalingState === "stable"` 双重判断，避免 HTTP 应答回执与
`call.accepted` 信令同时触发导致 `have-local-offer` 异常。

入口：

- 家庭端首页头部「📞 通话」按钮 → 打开拨号面板；
- 聊天面板顶部「通话」按钮 → 直接预选当前聊天对象；
- `CallPanel` 在登录后常驻挂载（`:active="!!token"`），保证任何时候都能收到来电。

Android 打包需在 `apps/mobile-app/src/manifest.json` 的 `app-plus.distribute.android.permissions` 中声明
`CAMERA`、`RECORD_AUDIO`、`MODIFY_AUDIO_SETTINGS`（已预置），否则 WebView 内 `getUserMedia` 直接失败。

## 9. 部署与配置

```bash
# 1) 生成 TURN 静态密钥
openssl rand -hex 32

# 2) 写入 infra/.env
FAMILY_TURN_SECRET=<上一步的值>
FAMILY_TURN_URLS=turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp
FAMILY_STUN_URLS=stun:turn.example.com:3478

# 3) 放行端口
# 3478/udp、3478/tcp、49160-49200/udp

# 4) 启动
cd infra && docker compose up -d coturn family-media-svc family-gateway
```

配置项（`family.media.*`，全部可用环境变量覆盖）：

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `FAMILY_MEDIA_MAX_PARTICIPANTS` | 8 | 单通话人数上限（含发起者） |
| `FAMILY_MEDIA_RING_TIMEOUT_SECONDS` | 45 | 无人接听超时 |
| `FAMILY_MEDIA_RECONNECT_GRACE_SECONDS` | 30 | 断线宽限 |
| `FAMILY_TURN_SECRET` | 空 | 空则只下发 STUN |
| `FAMILY_TURN_TTL_SECONDS` | 3600 | TURN 凭据有效期 |
| `FAMILY_MESSAGING_ENABLED` | false（compose 中为 true） | 多副本必须开启，信令跨实例 |
| `FAMILY_GATEWAY_CORS_ENABLED` | local 为 true | 本地 H5 跨域放行；生产同源代理时保持关闭 |
| `FAMILY_GATEWAY_CORS_ORIGINS` | `http://127.0.0.1:5173,http://localhost:5173` | CORS 白名单 |

**HTTPS 强制**：浏览器只在 HTTPS 或 `localhost` 下允许 `getUserMedia`。局域网真机调试需自签证书或用
`chrome://flags/#unsafely-treat-insecure-origin-as-secure` 临时放行，否则界面会提示「未获得麦克风/摄像头权限」。

### 10.2 本地端到端联调（含真实浏览器出图）

本机需要 JDK 21（后端按 21 编译，`java -version` 是 17 会报 `UnsupportedClassVersionError`），并按以下顺序起三个服务：

```bash
cd backend
# 用户服务（8081）、媒体服务（8090）、网关（8080）
SERVER_PROFILES=local
SPRING_PROFILES_ACTIVE=local FAMILY_JWT_SECRET=local-development-secret-32-characters-min \
  java -jar family-user-svc/target/family-user-svc-0.1.0-SNAPSHOT.jar
SPRING_PROFILES_ACTIVE=local FAMILY_JWT_SECRET=local-development-secret-32-characters-min \
  java -jar family-media-svc/target/family-media-svc-0.1.0-SNAPSHOT.jar
SPRING_PROFILES_ACTIVE=local FAMILY_JWT_SECRET=local-development-secret-32-characters-min \
  java -jar family-gateway/target/family-gateway-0.1.0-SNAPSHOT.jar
```

本地库是 H2 文件库，`local` profile 会引导管理员账号 `19900000001 / local-admin-123456`。

前端与脚本：

```bash
cd apps/mini-family && npx uni build -p h5
python -m http.server 5173 --bind 127.0.0.1 --directory dist/build/h5

cd scripts && npm i        # 安装 playwright（使用本机 Edge，不额外下载浏览器）
export FAMILY_MEMBER_PASSWORD='<成员一口令>'          # 管理员默认口令见下，成员口令由注册时设定
export FAMILY_MEMBER_NAME='冒烟成员'                  # 拨号面板里被叫的显示名，需与实际成员一致
export FAMILY_MEMBER2_PASSWORD='<成员二口令>'         # 仅 3 人脚本需要，缺省复用成员一
node call-smoke.mjs            # 纯信令链路：换票 → WS → 呼叫 → 接听 → SDP 转发 → 挂断 → 历史
node call-browser-smoke.mjs    # 真实浏览器：两个上下文互打，断言远端画面真的出图
node call-browser-group.mjs    # 真实浏览器：3 人网状通话，断言每端都有 2 路 live 远端画面
```

账号一律从环境变量读取（`FAMILY_ADMIN_PHONE/PASSWORD`、`FAMILY_MEMBER_*`、`FAMILY_MEMBER2_*`），
`scripts/accounts.mjs` 只保留 local profile 引导用的默认管理员手机号与口令，成员口令不写进仓库。

`call-browser-smoke.mjs` 用 `--use-fake-device-for-media-stream` 提供虚拟摄像头，并**逐 tile 断言**：
远端 tile 里必须有 `<video>`、`videoWidth > 0`、轨道 `readyState === "live"`。只看页面上存在一个
video 是不够的——那只可能是本地预览，这正是本次联调踩到的坑。

> 注意：宿主环境若注入了 `SERVER__PORT` 之类的变量，会覆盖 `server.port`，导致服务起在随机端口。
> 启动前 `env -u SERVER__PORT` 或显式传 `--server.port`。

## 11. 联调中定位到的真实缺陷（已修复）

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 能接通、双方都对端有声音，但对方画面永远是头像占位 | 接听时 `accept()` 与 `call.accepted` 回执同时调用 `startMedia`，并发进入 `prepareMedia` 各建了一个 `MeshRtc`，其中一个未完成采集就被用来 `createOffer`；没有轨道时 `max-bundle` 直接报 `session description has no BUNDLE group`，offer 从未发出 | `prepareMedia` 用 `preparing` Promise 做并发去重，采集完成后才赋值 `mesh`；`offerTo` 增加 `if (!this.local) await this.openLocal()` 兜底 |
| 偶发「WebSocket 握手 429」，之后整通电话打不通 | 早期 `RateLimitFilter` 按 IP 每秒 10 次限流且无开关，把 WS 升级请求也算进去；握手被拒后客户端不会重试 | 该过滤器改为默认关闭（`family.gateway.rate-limit.simple.enabled`），并对 `Upgrade: websocket` 放行；令牌桶限流同样放行 WS |
| 本地 H5（5173）调网关（8080）全部跨域失败 | 网关没有任何 CORS 配置 | 新增 `GatewayCorsConfiguration`，仅 `family.gateway.cors.enabled=true`（local 默认开）时生效，白名单来源 |
| 拨号面板一直显示「正在加载家庭成员…」 | 成员接口失败被 `catch {}` 静默吞掉 | 记录 `rosterError` 并在面板内展示，`openDial` 时若名单为空自动重试 |
| 语音通话全程无声；视频通话里对方一关摄像头声音也消失 | 远端音轨只由 `CallVideo`（`<video>`）播放，而它按 `kind === 'VIDEO' && tile.cam` 渲染：AUDIO 模式没有 video 元素，关摄像头后 tile 退化成头像占位，音轨随之失去播放载体 | 新增 `CallAudio.vue`（原生 `<audio>`，隐藏），在「无视频画面」的分支里承载远端音频；自动播放被拦截时挂一次性 `pointerdown` 重试 |

## 12. 已知限制与后续

1. **人数上限**：mesh 上行随人数线性增长，上限 8 人。SFU 改造已定案 LiveKit 自建（2026-11-24），届时客户端只保留一路上行、支持 20+ 人；信令状态机保留、媒体层可插拔，mesh 作为回滚通道。详见 `docs/LiveKit-SFU改造方案.md`。
2. **移动端后台**：APP 切到后台后 WebView 可能暂停采集/播放，需要原生前台服务保活，属于打包阶段工作。
3. **小程序**：微信小程序不支持 WebRTC，需要 `live-pusher/live-player` + 腾讯云 TRTC，属另一套媒体方案。
4. **弱网**：当前未做码率自适应与 simulcast，弱网下依赖浏览器默认策略；后续可在 `setParameters` 层做手动降码率。
5. **通话记录 UI**：后端已提供 `/media/calls/history`，家庭端尚未做历史列表页面。
