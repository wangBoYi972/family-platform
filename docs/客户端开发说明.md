# 客户端开发说明

## 客户端目录

- `apps/admin-web`：Vue3 + Element Plus 管理端。
- `apps/mini-family`：家庭综合小程序，使用 uni-app Vue3。
- `apps/mini-archive`：档案小程序，使用 archive client 身份，只做登录 + 档案列表。
- `apps/mobile-app`：移动端精简壳，五个 tab（任务 / 日程 / 家庭圈 / 消息 / 我的家）全部复用 `apps/shared/panels` 的同一份面板，外加顶栏的全局搜索、通话与实时刷新；日程内含家庭日历与纪念日，家庭圈内含动态、相册与照片时光轴，我的家内含公告、文件、档案、成员。
- `apps/shared`：跨端共享代码。
  - `call/`：通话组件与信令的唯一一份（CallPanel / CallVideo / CallAudio / call-client / webrtc-mesh）。
  - `panels/`：家庭端与移动端共用的面板组件：TaskPanel / CalendarPanel / AnniversaryPanel / DynamicsPanel / AlbumsPanel / AlbumTimeline / NoticesPanel / FilesPanel / ArchivePanel / MembersPanel / ChatPanel / GlobalSearch，以及公用的 EntryEditor。
  - `uni-client.js`：uni-app 端请求封装的唯一实现（request / upload / loadImageUrl / login / register），
    两个 H5 端都只是薄薄一层 `src/utils/request.js` 转出口。
  - `paged-list.mjs`：分页纯逻辑（`pageQuery` / `hasMore` / `mergePage`），可在 node 下直接单测。
  - `use-paged-list.js`：分页列表状态机（refresh / loadMore / exhausted / error）。
  - `ListMore.vue`：列表底部「加载更多 / 没有更多了」的统一交互。
  - `navigation.mjs`：共享面板的跳转契约（`NAV_KEYS` 与两端的目标映射表），5 项 node 单测保证「新增数据源却漏配跳转」不会溜过去。
  - `family-socket.js` + `realtime.mjs`：实时刷新通道、合并窗口与消息帧回调，详见下文「实时刷新」。
  - `refresh-topics.mjs`：增量刷新的主题匹配（refresh 帧的 event 字段 → 面板主题，未知类型回退全量），4 项 node 单测。
  - `unread.mjs`：未读数汇总口径（`sumUnread`），面板与宿主共用，4 项单测。
  - `timeline-export.mjs`：时光轴导出单文件 HTML 纪念册（纯函数拼文档 + 平台分叉的图片转 data URL 与落盘），5 项 node 单测，详见下文「时光轴导出纪念册」。
  - `request-message.js`：四端共用的请求错误文案。
  
  各端通过 vite 别名 `@shared` 引用，共享面板再用 `@app` 反查宿主应用的 `utils/request.js`。改一处四端同时生效。

## 共享面板的跳转约定

共享面板**不认识各端的 tab 名称**。搜索命中、纪念日「去日历看看」这类跳转只上报稳定的数据源 key
（`tasks` / `calendar` / `dynamics` / `albums` / `notices` / `archives` / `members` / `files`），
两端的目标结构一起放在 `apps/shared/navigation.mjs`，宿主只需一行：

```js
import { FAMILY_NAV_TARGETS, resolveNavTarget } from "@shared/navigation.mjs";
const next = resolveNavTarget(FAMILY_NAV_TARGETS, { key: "albums" }, { tab: "首页" }); // → 家庭圈 / 相册
```

- 映射表是**契约表**：新增搜索数据源时 `NAV_KEYS` 与两端的表都要加，`navigation.test.mjs` 会直接报出漏配的那一端。
- 未知 key 回落到各端给的兜底 tab，不允许出现「点了没反应」。
- 早先 `GlobalSearch` 直接把 `{ tab: "家庭圈", circleTab: "动态" }` 发出去，只有家庭端的结构对得上；
  共享化时必须改成 key，否则移动端会跳到不存在的 tab。

## 主题变量

共享面板只用 `--c-*` 语义色（`--c-primary` / `--c-ink` / `--c-line` / `--c-sky` / `--c-sage` / `--c-sand` / `--c-plum` 等），
品牌差异由各端的 `App.vue` / `theme.css` 重新赋值。**缺一个变量在 H5 上不会报错，只会静默丢样式**，
所以移动端 `App.vue` 里把 `--c-*` 整套补齐了，新增面板用到新变量时要同步补。

## 列表分页约定

后端列表接口统一接受 `page` / `size`（不传时保持旧的「取前 N 条」行为），但**不返回 total**，因此前端用
「本页返回条数 ≥ size」判断是否还有下一页，最坏情况是多请求一次空页，不会漏数据。

面板里统一这样接入：

```js
const { items, loading, loadingMore, exhausted, error, refresh, reload, loadMore } =
  usePagedList((page, size) => request(pageQuery("/tasks", page, size)));

async function load() { /* 用户主动触发：搜索、新建后回第一页 */ await refresh(); }
async function sync() { /* 实时事件触发：保持已翻到的位置 */ await reload(); }
defineExpose({ load, sync });
```

模板底部放 `<ListMore :count="items.length" :loading="loadingMore" :exhausted="exhausted" :has-error="!!error" @more="loadMore" />`。

注意筛选的位置，这两类情况不能混：

- **分页列表一律服务端筛选**：任务（`keyword` / `status`）、动态与相册（`keyword`）、文件（`keyword`）、档案（`keyword` / `category`）都拼进查询串，输入停顿 300ms 后从第一页重拉。分页和筛选同时存在时，客户端本地过滤只能覆盖当前一页，等于「搜不到旧数据」。
- `apps/shared/tasks.mjs` 的 `filterTasks` 仍保留，但只用于一次性把完整数据取到本地的场景（`TodayOverview` 的待办概览）。**不要**再在分页列表上用它。
- 管理端任务看板与内容页（公告 / 日历 / 档案 / 成员之外的三类）同样是服务端筛选 + 分页（每页 12 条），
  看板指标改由 `GET /api/tasks/stats` 提供；成员列表没有服务端关键字，仍是本地过滤。看板指标是家庭全局口径，**不能**用当前页数据累加，否则越翻越小。
- 筛选期间统计数字会失真（「全部文件 / 占用空间 / 档案总数」本来统计的就是列表内容）。文件与档案面板在筛选时**隐藏统计、改成显示结果条数**；未筛选但还没加载完时会提示「统计基于已加载的 N 条」。这两类提示都不要去掉，去掉就会被误读成数据丢失。

## 实时刷新

后端的广播链路一直都在（任何领域事件 → Outbox → `im-svc` → 同家庭在线连接收到 `{"type":"refresh"}`），
缺的是客户端，所以两台设备上的列表从来不会自己更新。现在由 `apps/shared/family-socket.js` 补上：

```js
// refresh 帧带事件类型（task.created / file.deleted…），按主题挑面板重拉
const refreshMap = [
  { ref: taskPanel, topics: ["task"] },
  { ref: todayOverview, topics: ["task", "calendar", "dynamic", "member"] },
  { ref: filesPanel, topics: ["file"] }   // …每个面板声明自己关心的主题
];
const familySocket = new FamilySocket({
  onRefresh: (count, events) => {
    const plan = refreshPlan(events, KNOWN_TOPICS);   // apps/shared/refresh-topics.mjs
    refreshMap.forEach(({ ref, topics }) => {
      if (!hitsTopic(plan, topics)) return;
      const instance = ref.value;
      if (instance) (instance.sync || instance.load)?.();  // 分页面板用 sync，别把人拽回第一页
    });
  },
  onStatus: status => { socketOpen.value = status === "open"; },
  onMessage: frame => {
    if (chatPanel.value) chatPanel.value.receive(frame);   // 消息帧直接上屏
    else refreshUnread();                                 // 聊天页没开，至少把角标更到最新
  }
});
onMounted(() => { if (token.value) { familySocket.connect(); refreshUnread(); } });
watch(token, value => (value ? familySocket.connect() : familySocket.close()));
```

- 连接走 `/ws/im`，与通话的 `/ws/call` 分开：前者只发刷新通知，后者带信令语义和 30 秒断线宽限。
- 一次上传会产生好几条事件，`realtime.mjs` 的 `createRefreshGate` 把 400ms 内的多次变化合并成一次刷新，
  并把窗口期内的事件类型收成 Set 一起交给 `onRefresh(count, events)`（6 项单测）。
- **增量刷新**：refresh 帧带 `event` 字段（如 `{"type":"refresh","event":"task.created"}`），
  主题取点号前的前缀（task）。`apps/shared/refresh-topics.mjs` 负责匹配，宿主只重拉关心该主题的面板——
  任务变了不必连相册一起刷。两条兜底：帧没带 event（旧版后端）或类型前端不认识（新增事件没进映射表），
  都回退全量刷新，宁可多刷不能漏。4 项单测。
- 后端侧 `FamilyEventConsumer` 走结构化帧广播（`notifyFamilyEvent`）下发刷新：这同时修了一个多实例问题——
  Rabbit 队列是竞争消费，事件只会被一台实例收到，之前只发本机连接的话，其它实例上的客户端永远收不到刷新。
- 只重拉**当前挂载**的面板：面板都是 `v-if` 渲染，没显示的那块不会白跑请求。
- **`ChatPanel` 不参与刷新**：重拉会把正在输入的草稿和滚动位置一起冲掉。
- **消息走推送，不走刷新**：新消息由后端下发 `{"type":"message",...}` 帧，帧里带齐 id / 发送人 / 类型 / 正文 / 时间，
  `ChatPanel.receive()` 收到直接 `append`（按 id 与 clientId 去重，和轮询拿到的同一条不会重复上屏）。
  会话不是当前打开的那条时，只刷新会话列表拿未读数，**不把人从正在看的那一屏切走**。
- **已读回执也走推送**：后端在已读水位真的前进时下发 `{"type":"read",conversationId,userId,lastMessageId}`。
  合并口径抽到 `apps/shared/receipts.mjs`：`mergeReceipt` 只进不退（断线重连后旧帧后到，不能让「已读」退回去），
  `readMemberIds` 排除自己（自己总是读过自己发的消息，混进名单会显示成「家人」）。5 项单测。
- **回执轮询只在断线时保留**：面板新增 `live`（宿主传 `socketOpen`）。连着实时通道时不拉 `/read`，
  发完消息也不再多一次往返；断开时 `poll` 的 else 分支才补一次。早先每 4 秒拉一次回执，只为了看「谁已读」。
- **语音消息**：长按输入框左侧的 🎙 说话，松开发送（移出/`touchcancel` 取消，短于 800ms 按误触丢弃）。
  后端 `kind=AUDIO` 本就支持，这次补的是客户端：录音用 `uni.getRecorderManager`（格式 mp3，后端 MIME 表里有），
  播放先把文件鉴权下载成临时路径再 `InnerAudioContext` 播——它不支持自定义请求头，直接给下载 URL 会 401。
  每次播放新建上下文：它的事件是叠加注册的，复用会越挂越多。
  **H5 端录不了**：uni-app 的 H5 `getRecorderManager` 是「不支持」桩实现，一调就抛——面板把它兜成明确提示
  「可在小程序里使用」；播放端 H5 是真实现（HTML5 Audio），能收能听。
- **聊天传文件**：输入框右侧「文件」按钮，后端 `kind=FILE` 只要求附件是家庭共享（不限 mime）。
  选择器统一走 `uni.chooseFile`：H5 是 `input[type=file]` 真实现；微信小程序没有系统文件选择器，
  uni-app 把它映射到 `wx.chooseMessageFile`（从聊天记录选），同一调用两端都能跑，不用条件编译。
  气泡显示文件名/大小（进会话时并行拉 `/files/{id}/metadata`，拉不到就显示「文件 · 点击下载」）；
  点开先鉴权下载成本地路径（`InnerAudioContext`/`openDocument` 都不支持带鉴权头的 URL），H5 用 `<a download>` 触发另存，
  小程序/App 走 `uni.openDocument`（不支持的类型提示后放弃，不崩）。
- **消息撤回**：长按自己的气泡撤回，发出后 2 分钟内有效（服务端权威判断，窗口外返回 400）。
  撤回是软删：消息保留、正文清空，所有人看到「此消息已撤回」占位（分页不塌）；
  实时下发 `message.deleted` 帧，面板挂载时就地改占位，没挂载时宿主走 refresh 重拉。
  重复撤回幂等成功。**H5 桌面端没有长按**——触摸设备与小程序可用，桌面浏览器后续可加悬停按钮。
- **多设备角标对齐**：自己在另一台设备读过的会话，本机角标要跟着清。`read` 帧里带 `userId`，
  面板挂载时只在「是自己读的且不是当前会话」才重拉会话列表（别人的已读不影响我的未读数，不白跑）；
  面板没挂载时宿主对 `read` 帧也调 `refreshUnread()`，否则角标要等下一条新消息才清得掉。
- **轮询降级为兜底**：面板新增 `pollMs`，宿主在通道连上时传 20000、断开时传 4000（`socketOpen`）。
  推送负责及时性，轮询只负责「推送漏了也能自己追上」——所以断线时聊天仍然自动更新，只是慢一点。
  面板内的提示文案跟着 `pollMs` 变（「实时推送中 · 断线自动重连」/「每 4 秒自动获取新消息」）。
  判定依据是 `live` 而不是 `pollMs > 5000` 这类阈值猜测——配置一变就会说谎。
- **未读角标要有兜底**：聊天页没打开时 `ChatPanel` 根本没挂载，收不到推送也发不出 `unread-change`，
  角标会一直停在 0。宿主在 `onMessage` 里发现面板不在，就自己拉一次会话列表用 `sumUnread()` 求和
  （`apps/shared/unread.mjs`，与面板内同一套口径，4 项单测）。
- **窄屏聊天两屏切换**：≤760px 时列表与聊天区不再上下堆叠（点了会话聊天区还在屏幕下方，看着像没反应），
  而是列表页/聊天页互斥显示——根节点 `in-room` 类 + 媒体查询纯 CSS 控制，选中会话即进聊天页，
  左上角「‹ 会话」返回列表并停轮询。窄屏不再自动打开第一个会话（列表页的未读红点就是首页）。
  宽屏维持左右并排、自动打开第一个会话。未读红点 = 会话项右侧数字角标：
  来消息（推送或兜底轮询）→ 重拉会话列表 → 红点出现；点进会话 → `markRead` → 红点消除。
- **全局搜索在服务端检索**：`GlobalSearch` 原来把八类数据整份拉回来本地 `includes`，只搜得到「第一页」——
  家里数据一多，明明存在的公告/档案就是搜不出来，而且每次打开搜索都要打八个接口下载全家内容。
  现在按 `keyword + page=1&size=8` 下推（七个接口本就支持，成员接口没有关键字，只有几个人才本地筛），
  输入停顿 220ms 才发请求，并用序号丢弃「打字快时后发先回」的过期结果。
- **分页面板用 `sync()`（就地刷新），不是 `load()`**：`load()` 等价于 `refresh()`，会重置到第一页；
  用户正翻到第 3 页时，别人改了一条数据就把他拽回顶部，比不刷新更烦人。`reload()` 重拉 1..N 页原地替换，
  失败时保留原内容只记错误。重拉后页码由 `summarizeReload` 重新推算（中途有人删数据会让后面的页变短，
  页码必须收回来，否则下一次「加载更多」会跳过一段）。动态与相册还会复用已解析的图片地址，不重复换一次 URL。
- 重连后立刻 `flushNow()` 补一次，断线期间错过的变化不会一直显示旧数据；票据 401 直接停止重连，交给重新登录。


## 微信订阅消息（服务通知）

家人不打开应用也能收到「有新消息」的微信服务通知。链路是「授权一次 = 可推一条」的一次性配额模型：

1. **绑定 openid**（`apps/shared/wx-notify.mjs` 的 `bindWxSession`）：登录后在微信小程序端
   `uni.login` 拿 code，`POST /api/wx/session` 由 user-svc `code2session` 换 openid 绑到账号。
   没有 openid 就没有收件地址。非微信端是空操作，任何失败都静默。
2. **申请授权**（`requestNotify`）：微信要求 `requestSubscribeMessage` 必须在用户点击的同步链里触发——
   `ChatPanel.sendText` 在发送前同步调用（不 await，弹窗归弹窗，消息该发就发）。
   accept 的模板上报 `POST /api/wx/subscriptions` 落一条配额；用户明确拒绝过则 7 天内不再弹，
   且同一会话只问一次——反复弹窗比不打扰更招人烦。
3. **离线推送**：后端 `ImServiceImpl` 发消息后，只对**不在线**的收件人（在线注册表按用户判断）
   经 Feign 调 user-svc `POST /api/wx/notify`，消耗一条配额、按模板配置把语义字段（sender/preview）
   翻译成微信字段 ID 后调 `subscribe/send`。人就在应用里时实时帧已秒到，再弹服务通知是打扰。

**当前是待凭证状态**：`family.wx.enabled=false` 时整条链路静默跳过（bind 503、notify skipped），
客户端已按此兜底。上线前在微信后台申请订阅消息模板，把 appid/secret/模板 ID 填进
user-svc `application.yml` 的 `family.wx`（模板字段映射 `fields` 按申请时的字段顺序填），代码不用动。

## 时光轴导出纪念册

`AlbumTimeline` 顶部有「导出纪念册」按钮，把当前已加载的时光轴（相册 + 动态、按月分组）
生成一份**单文件 HTML**：图片转成 base64 data URL 内嵌，不依赖网络和登录态，发给家人
双击即开，浏览器里 Ctrl+P 可直接存成 PDF。实现都在 `apps/shared/timeline-export.mjs`：

- `buildTimelineHtml`：纯函数，分组渲染 + 时刻/照片统计，输入直接复用面板的分组计算
  结果（转换时只换图片 URL），单测覆盖转义、统计、空态、失败占位。
- `toDataUrl`：平台分叉——H5 的 blob URL 走 `fetch` + `FileReader`；小程序的本地临时
  路径走 `FileSystemManager.readFile` 读 base64（按扩展名猜 MIME）。单张失败返回
  null，文档里落「图片未能嵌入」占位，不阻塞整本。
- `exportTimelineHtml`：H5 用 `<a download>` 触发另存；小程序写入 `USER_DATA_PATH`
  后尝试 `shareFileMessage` 转发，不支持时弹窗告知文件路径。

**导出的就是眼前这份**：时光轴面板为控制流量只加载最近 24 个时刻、每条最多 6 张图，
导出同样以此为界——要导更多，先在面板里筛选月份再导。全量导出等有真实需求再做。

## 纪念日提醒

折算、挑选、去重、文案都在 `apps/shared/anniversary-remind.mjs`，一份实现三处复用
（AnniversaryPanel 的列表折算 + 两个宿主的当天提醒）：

- `buildAnniversary(row, today)`：yearly 折算到今年、今年过了折明年并累计「第 N 个」；
  一次性日程已过去 days 为负。面板的列表与宿主的提醒共用同一份口径，改折算不会两处漂移。
- **当天提醒**：登录进来当天有到期日程就 `uni.showModal` 弹一次（列出条目与「第 N 个」，
  超过 3 条截断带总数），storage 按日期去重——同一天只弹一次，跨天自然失效。
- **刻意的克制**：只弹「今天」，3 天内临近的靠面板红标提示——弹窗连着弹只会被关掉
  再也不看。提醒失败一律静默，它是锦上添花不是必需品。
- 服务端推送（每天定时扫 + 微信订阅消息）等微信凭证到位后基于第 5 项链路再做。

## 审计可视化

家庭档案的访问审计有两层视图：

- **单档案**：展开详情后的「访问记录」，最近 6 条文字列表（`GET /archives/{id}/audit`，
  档案所有者可见）。
- **家庭总览**（仅管理员）：`ArchivePanel` 顶部「访问总览（近 30 天）」折叠块，调
  `GET /archives/audit/summary`（archive-svc 服务端聚合近 30 天日志，按人/按天/按动作
  三组计数；能看到私有档案的访问记录，所以 `requireAdmin`）。前端纯 CSS 条形图渲染：
  每日柱状图（缺的日子补零，空档期也是信息）+ 谁看得最多横条 + 动作分布标签，
  不引图表库，四端零依赖。补零与占比计算在 `apps/shared/audit-view.mjs`（4 项单测）。

## 本地运行

在客户端目录执行：

```powershell
pnpm install
$env:VITE_API_BASE_URL="http://127.0.0.1:8080/api"
pnpm dev:h5
```

微信开发者工具或 Android 真机使用 uni-app 官方运行方式打开对应目录。正式客户端使用手机号和密码登录，不保存密码，只保存短期访问令牌。测试验证码仅在后端 `local` profile 开启，不能用于生产。

管理员首次初始化后通过管理端“账号与家庭成员”创建成员账号和设置密码。成员修改密码后旧设备必须重新登录；停用成员会立即阻断已有令牌的访问。

## 身份边界

家庭端登录 client 为 `family`，档案端登录 client 为 `archive`。服务端会校验 JWT、会话、家庭成员资格和请求方法；客户端不提交 householdId 作为可信权限依据。
