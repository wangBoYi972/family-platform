# 客户端开发说明

## 客户端目录

- `apps/admin-web`：Vue3 + Element Plus 管理端。
- `apps/mini-family`：家庭综合小程序，使用 uni-app Vue3。
- `apps/mini-archive`：档案小程序，使用 archive client 身份，只做登录 + 档案列表。
- `apps/mobile-app`：移动端精简壳，五个 tab（任务 / 日程 / 家庭圈 / 消息 / 我的家）全部复用 `apps/shared/panels` 的同一份面板，外加顶栏的全局搜索与通话；日程内含家庭日历与纪念日，家庭圈内含动态与相册，我的家内含公告、文件、档案、成员。
- `apps/shared`：跨端共享代码。
  - `call/`：通话组件与信令的唯一一份（CallPanel / CallVideo / CallAudio / call-client / webrtc-mesh）。
  - `panels/`：家庭端与移动端共用的面板组件：TaskPanel / CalendarPanel / AnniversaryPanel / DynamicsPanel / AlbumsPanel / NoticesPanel / FilesPanel / ArchivePanel / MembersPanel / ChatPanel / GlobalSearch，以及公用的 EntryEditor。
  - `uni-client.js`：uni-app 端请求封装的唯一实现（request / upload / loadImageUrl / login / register），
    两个 H5 端都只是薄薄一层 `src/utils/request.js` 转出口。
  - `paged-list.mjs`：分页纯逻辑（`pageQuery` / `hasMore` / `mergePage`），可在 node 下直接单测。
  - `use-paged-list.js`：分页列表状态机（refresh / loadMore / exhausted / error）。
  - `ListMore.vue`：列表底部「加载更多 / 没有更多了」的统一交互。
  - `navigation.mjs`：共享面板的跳转契约（`NAV_KEYS` 与两端的目标映射表），5 项 node 单测保证「新增数据源却漏配跳转」不会溜过去。
  - `request-message.js`：四端共用的请求错误文案。
  
  各端通过 vite 别名 `@shared` 引用，共享面板再用 `@app` 反查宿主应用的 `utils/request.js`。改一处四端同时生效。

## 共享面板的跳转约定

共享面板**不认识各端的 tab 名称**。搜索命中、纪念日「去日历看看」这类跳转只上报稳定的数据源 key
（`tasks` / `calendar` / `dynamics` / `albums` / `notices` / `archives` / `members` / `files`），
两端的目标结构一起放在 `apps/shared/navigation.mjs`，宿主只需一行：

```js
import { FAMILY_NAV_TARGETS, resolveNavTarget } from "@shared/navigation.mjs";
const next = resolveNavTarget(FAMILY_NAV_TARGETS, { key: "albums" }, { tab: "首页" }); // → 家庭圈 / 相册
```

- 映射表是**契约表**：新增搜索数据源时 `NAV_KEYS` 与两端的表都要加，`navigation.test.mjs` 会直接报出漏配的那一端。
- 未知 key 回落到各端给的兜底 tab，不允许出现「点了没反应」。
- 早先 `GlobalSearch` 直接把 `{ tab: "家庭圈", circleTab: "动态" }` 发出去，只有家庭端的结构对得上；
  共享化时必须改成 key，否则移动端会跳到不存在的 tab。

## 主题变量

共享面板只用 `--c-*` 语义色（`--c-primary` / `--c-ink` / `--c-line` / `--c-sky` / `--c-sage` / `--c-sand` / `--c-plum` 等），
品牌差异由各端的 `App.vue` / `theme.css` 重新赋值。**缺一个变量在 H5 上不会报错，只会静默丢样式**，
所以移动端 `App.vue` 里把 `--c-*` 整套补齐了，新增面板用到新变量时要同步补。

## 列表分页约定

后端列表接口统一接受 `page` / `size`（不传时保持旧的「取前 N 条」行为），但**不返回 total**，因此前端用
「本页返回条数 ≥ size」判断是否还有下一页，最坏情况是多请求一次空页，不会漏数据。

面板里统一这样接入：

```js
const { items, loading, loadingMore, exhausted, error, refresh, loadMore } =
  usePagedList((page, size) => request(pageQuery("/tasks", page, size)));
```

模板底部放 `<ListMore :count="items.length" :loading="loadingMore" :exhausted="exhausted" :has-error="!!error" @more="loadMore" />`。

注意筛选的位置，这两类情况不能混：

- **分页列表一律服务端筛选**：任务（`keyword` / `status`）、动态与相册（`keyword`）、文件（`keyword`）、档案（`keyword` / `category`）都拼进查询串，输入停顿 300ms 后从第一页重拉。分页和筛选同时存在时，客户端本地过滤只能覆盖当前一页，等于「搜不到旧数据」。
- `apps/shared/tasks.mjs` 的 `filterTasks` 仍保留，但只用于一次性把完整数据取到本地的场景（管理端看板的当前页内过滤、`TodayOverview` 的待办概览）。**不要**再在分页列表上用它。
- 筛选期间统计数字会失真（「全部文件 / 占用空间 / 档案总数」本来统计的就是列表内容）。文件与档案面板在筛选时**隐藏统计、改成显示结果条数**；未筛选但还没加载完时会提示「统计基于已加载的 N 条」。这两类提示都不要去掉，去掉就会被误读成数据丢失。

## 本地端口

| 应用 | 端口 | 说明 |
| --- | --- | --- |
| `admin-web` | 5173 | vite 默认 |
| `mini-family` | 5174 | 网关 CORS 已放行 |
| `mobile-app` | 5175 | 原先默认 5173 会与管理端撞端口 |
| `mini-archive` | 5176 | 网关 CORS 已放行 |

网关 `application-local.yml` 的 `family.gateway.cors.allowed-origins` 需包含以上四个来源；跨端引用 `apps/shared`
属于「应用根目录之外」，各端 vite 配置里的 `server.fs.allow` 已放行，删掉会导致 `dev` 报 outside of allow list。

## 本地运行

在客户端目录执行：

```powershell
pnpm install
$env:VITE_API_BASE_URL="http://127.0.0.1:8080/api"
pnpm dev:h5
```

微信开发者工具或 Android 真机使用 uni-app 官方运行方式打开对应目录。正式客户端使用手机号和密码登录，不保存密码，只保存短期访问令牌。测试验证码仅在后端 `local` profile 开启，不能用于生产。

管理员首次初始化后通过管理端“账号与家庭成员”创建成员账号和设置密码。成员修改密码后旧设备必须重新登录；停用成员会立即阻断已有令牌的访问。

## 身份边界

家庭端登录 client 为 `family`，档案端登录 client 为 `archive`。服务端会校验 JWT、会话、家庭成员资格和请求方法；客户端不提交 householdId 作为可信权限依据。
